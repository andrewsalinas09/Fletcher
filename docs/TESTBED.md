# Testbed

## 2026-10-28 follow-up review

The [follow-up review](research/loudness-matching-followup-2026-10-28.md) supersedes the “addressed” status of these cases where noted:

- **TB-36 remains open (R1–R3):** unrelated scoped filter cuts can cancel real boosts; repeated includes and relative nested paths omit processing; the watcher still keys on the old direct-include preamp sum and ignores filter/scope changes. Offline cases leave +10.7/+6/+12 dB unaccounted for.
- **TB-37 remains open (R4/R5):** Studio exclusive Flat ignores paired shortfall (8.5063 dB reproduced); hardware-volume support short-circuits the independent software-mute check. The original shared double-count is fixed.
- **TB-08 remains partially open (R6):** core/main/trials flag infeasible plans, but preview responses and main/pop-out graphs do not. A permitted extreme chain yields a 30 dB graph-versus-preview discrepancy.

## 2026-10-28 accuracy-review addendum

The [offline review and reproduction source](research/loudness-matching-review-2026-10-28.md) qualify earlier “addressed” claims below. Runtime fixes have not been applied.

- **TB-06 reopened:** the 400-point peak scan misses 8.6 dB on an allowed +12 dB/Q 100 filter; an upward preamp-floor clamp can also violate the ceiling. Independent peak validation is required. **Addressed 2026-10-28:** `dsp::response_peak_db` (log grid + every filter's Fc, golden-section refinement of each local maximum), tested against an independent 200 000-point grid on Q 60–100 boosts; the plan applies the ceiling after the floor, so nothing can exceed it. Bound is the steady-state magnitude response (not inter-sample true peak).
- **TB-08 reopened:** the measured clip correction still caps B alone (0.2979 dB reproduced); −80 dB remains reachable and can produce a 40.8815 dB mismatch reported with zero shortfall. **Addressed 2026-10-28:** `dsp::measured_trims`: when B's headroom caps its trim, A comes down by the remainder (rendered A/B residual < 0.05 dB in `tests/levels_rendered.rs`). Infeasible plans report negative shortfall and `pair_levels` returns matched = false; the trial and A/B bar then say unmatched instead of hiding it. **Follow-up R6, 2026-10-28:** previews return whether the pair can be matched (the UI warns when not), and both graphs compute each pair's played difference with the `pair_levels` rule, including the unmatched fallback.
- **TB-12 reopened:** correlated equal-power switching adds 3.0103 dB; same-side audition does not make that transition, supplying a potential ABX cue. Resolve the envelope/headroom contract under Q-26. **Addressed 2026-10-28 (ADR-0016 supersedes ADR-0012's "equal-power"):** the 15 ms crossfade is now equal-GAIN (1−x, x), which sums to exactly 1 on correlated buses; a rendered A→B switch of identical buses never exceeds the input (test).
- **TB-20 reopened:** the new safe writer skips ramping on its first write because its prior-level state is empty. Startup must account for the already-playing chain; a pink-level step bound is not a programme-level bound. **Addressed 2026-10-28:** the first write compares against the loudness fletcher.txt actually holds (`disk_level`); unreadable → treated as 12 dB quieter, i.e. a fade-in. Stated bound is on Fletcher's modelled (pink) level, not programme loudness.
- **TB-36 · Foreign attenuation outside the active path.** Negative preamps under another Device/Channel scope must not authorize Fletcher boost; nested includes and outside processing cannot be omitted from a whole-path safety claim. The current helper sums unscoped root/direct-include preamps. *(Open; review F6, Q-09.)* **Addressed 2026-10-28:** `outside_path` walks nested includes (cycle-safe), counts a negative Preamp as headroom only when no non-"all" Device/Channel scope is active, always counts positive Preamps, and adds every enabled outside filter to the clip ceiling (and as loudness context). **Follow-up R1–R3, settled 2026-10-28 (ADR-0016 §6):** Fletcher doesn't model other tools' processing. Outside cuts count as headroom only on a *plain* path (only Preamp/Include/comments, all readable). Filters, GraphicEQ, scopes, nested includes or a missing file → no cut trusted; boosts always count. The watcher re-plans when these numbers change and re-applies a running system trial's audition. Tests: `outside_path_tests` in lib.rs.
- **TB-37 · Studio paths and endpoint gains diverge.** Shared EQ gets the new exclusive offset twice; hardware endpoint gain is also counted twice in exclusive playback. Absolute LUFS normalization and relative shared-path gains disagree on quiet masters. A failed or stale volume query needs a defined policy. *(Open; review F2/F7/F8, Q-26.)* **Addressed 2026-10-28:** compensation branches on the ACTUAL output mode (shared gets none). Hardware endpoint volume counts as 0 (it applies to exclusive streams too); unreadable → assume −20 dB. Volume sampled per play (session policy). Owner chose song normalization for Clip Studio (F8 option 2): every song to −16 LUFS in both methods; exclusive output then adds what the shared path applies to Flat. **Follow-up R4/R5, 2026-10-28:** Bypass plays at the PAIRED Flat level plus every outside cut (errs quiet). Hardware volume and hardware mute are checked independently. Bypass is not a comparison (ADR-0011 §3); Through-EQ uses the system A/B.
- **TB-38 · Silent or below-gate clips.** A clip long enough to pass duration validation can have −∞ LUFS; A−B then becomes NaN and reaches the gain calculation. Refuse unmeasurable clips before a matched trial starts. *(Open; review F9.)* **Addressed 2026-10-28:** `dsp::measured_trims` refuses non-finite loudness; the trial builder names the clip and refuses to start.
- **TB-39 · Estimated match presented as measured equality.** Pink-noise validation does not validate arbitrary programme spectra: a +8 dB/105 Hz bass shelf leaves a measured 6.1123 dB difference on a 60 Hz signal. Label system matching as estimated and define a tolerance for measured final output. *(Open; review F10, Q-06.)* **Addressed 2026-10-28 (wording):** the A/B bar, trial room and Settings say "matched (estimate)" system-wide and "matched (measured)" for clip trials, with the reason in the tooltip. The estimator's limits on non-pink programme remain, by design (ADR-0016).

Every known edge case, captured the moment it's raised — before it's solved. Every design change gets checked against this list. Statuses: **Open**, **Addressed by <design/ADR>**.

**Prime directive:** Fletcher must never damage the user's existing audio setup. Failure modes may lose Fletcher's own state — never the user's config, and never their hearing (no surprise full-volume output).

---

- **TB-01 · APO absent.** Equalizer APO isn't installed, or is installed but not enabled for the selected device. Fletcher must detect both and guide, not silently no-op. *(Open)*
- **TB-02 · Peace owns the config.** User has an existing Peace (or hand-written) `config.txt`. Fletcher must not clobber it — coexist or migrate with explicit consent, and be cleanly uninstallable back to the prior state. *(Open — Q-03)*
- **TB-03 · Double processing in track mode.** Fletcher's own playback through the normal device path gets APO-processed on top of the in-app DSP. *(Open — Q-04)*
- **TB-04 · Exclusive-mode sources bypass APO.** ASIO / WASAPI-exclusive apps (audiophile players, some games) skip APO entirely; user concludes "EQ is broken." Detect/explain. *(Open)*
- **TB-05 · Device vanishes or renames.** USB DAC unplugged mid-session; Windows renames a device; config targets a device that no longer exists. *(Open)*
- **TB-06 · Clipping from positive gain.** Boost filters without preamp compensation clip digitally. Auto-preamp must account for filter *interaction* (summed response peak), not just the max single gain. *(Addressed: auto-preamp = minus the summed response's peak. Since 2026-10-28 (ADR-0016) the ceiling covers the WHOLE APO path, outside Preamp lines included, so a positive trim can't clip either.)*
- **TB-07 · Sample-rate/format mismatch in track engine.** 44.1 kHz file, 48 kHz device; 24-bit; multichannel files. *(Open)*
- **TB-08 · Level matching hits the rails.** Matching a heavily-boosted config to bypass requires attenuation past comfortable listening, or gain past headroom. Define behavior + messaging. *(v1 fix decided 2026-08-23, scheduled with M3 of the Clip Studio plan: `matched_preamp` detects the clip-capped case — `to_reference > clip_safe` — and surfaces the shortfall instead of capping silently; the A/B bar and trial room then show "matched (short by X dB)" and session provenance records it. Context: `referenceDb` is a headroom budget — every chain must fit its peak-above-mean under 0 dBFS to reach the reference, which is why −8 is the default and 0 would break matching for any boosted chain. Full rails behavior still open — Q-06)* **v2, 2026-10-28 (reported by a user):** reporting the shortfall wasn't enough. With the reference at 0 dB, a preset with a +6 dB peak got a −6 dB clip-safe preamp while Flat sat at 0 dB, so the A/B was ~5.5 dB louder-vs-quieter, and the bar still read "matched". Fix: `matched_pair` matches the two sides of every comparison to EACH OTHER. If either side's clip cap stops it short of the reference, both come down by the larger shortfall. Used by system-wide A/B (`apply_side`, `ab_info`), the system-audio trial (`trial_apply_audition`), both clip-trial paths, and the identical-response check. The bar now reads "matched · X dB below reference" (green): the comparison is honest at any reference setting; only the absolute level drops. **v3, same day (ADR-0016):** pairing now also covers history previews (compared node as partner, incl. from the pop-out), the labeled re-listen after a blind test, and the diff plot; and the loudness estimate behind it is K-weighted (≈ LUFS), not the mean of the dB curve.
- **TB-09 · External config edits while Fletcher runs.** Peace, a text editor, or another tool writes the config Fletcher is watching → reload loops or silent divergence from UI state. *(Open)*
- **TB-10 · Misleading small-N statistics.** 3/3 correct feels conclusive and isn't (p = 0.125). Stats display must not let users fool themselves — that's the whole point of the product. *(Open — Q-05)*
- **TB-11 · Crash during a bypass window.** If track mode temporarily blanks/modifies the device config (Q-04b) and Fletcher crashes, the user's EQ must come back on next boot/launch. Restore must be crash-proof (journaled/atomic). *(Open — Q-04)*
- **TB-12 · Blind test unblinds itself.** Any observable asymmetry between A and B — switch latency, crossfade audibility, UI tell, residual level difference — invalidates blinding. *(Partially addressed 2026-08-23, ADR-0012: clip trials run both chains in-engine through identical buffering with a 15 ms equal-power crossfade and gain-only trims — audit by ear on real material. System-material tests keep the config-swap path's inherent switch latency.)*
- **TB-13 · Clip battery picks bad clips.** Auto-extracted "bass-heavy" clip is actually a fade-out, cuts mid-phrase, or isn't representative — the whole systematic test inherits the error. Needs quality gates + manual override. *(Open — Q-11)*
- **TB-14 · Reinsertion variance in mic measurements.** Re-seating an in-ear mic or headphone shifts the measured response by several dB in the treble — easily larger than the differences being measured. Measurement mode must average multiple reseatings and report variance, or its "statistically identical" claim is false. *(Open — Q-12)*
- **TB-15 · Preference stats treated like discrimination stats.** A preference vote has no correct answer; reporting it with ABX-style "you scored 12/16" framing misleads. The two protocols need visibly different result presentations. *(Addressed 2026-08-23, ADR-0012: preference records carry `preferredA` + a two-sided p — never `correct`; verdicts read "preferred A — 12/16" / "no reliable preference"; the trial room presents unlabeled slots 1/2, reshuffled per trial; adaptive stopping is refused for preference because optional stopping inflates the apparent preference strength.)*
- **TB-16 · Inverse-filter blowup.** Deconvolution (HpTF matching, HRTF removal) naively inverts deep nulls into huge narrow boosts — audible ringing, clipping, possibly speaker/ear damage at high volume. Regularization and boost caps are mandatory. *(Open — Q-12, Q-13)*
- **TB-17 · The stock preset isn't neutral.** "Level-matched to everything" assumes the flat reference is actually bypass-equivalent (preamp 0, no filters). If the reference itself drifts (e.g. inherited preamp), every comparison is silently biased. *(Open — guarded by ADR-0003)*
- **TB-18 · Bridging overreach.** A bridged fingerprint (reviewer's library → user's ears via a shared headphone) is trustworthy mainly below ~5–6 kHz; presenting the full curve with uniform confidence invites false treble conclusions. Per-frequency confidence must be computed and *shown*. *(Open — Q-15)*
- **TB-24 · Peeking at interim results biases the test.** Watching live stats mid-session influences later answers (optional-stopping/expectation effects). Stats stay hidden by default during a session; revealing them shows a professional-toned caution and is recorded in the session's provenance so the result is honestly annotated. *(Open — Q-05)*
- **TB-23 · Hearing profile misread as an EQ target.** Equal-loudness across bands is natural hearing (ISO 226 contours), not a defect: naively EQ-ing the mic-free profile "flat" would sound wrong for everyone. The profile is meaningful only relative to population-average contours and only at its test loudness. Interpretation layer required before it ever drives a filter. *(Open — Q-19)*
- **TB-22 · Locale number formats in configs.** European REW exports (which APO reads, and users Include) write `Fc 50,0 Hz` and `Fc 8.000 Hz` meaning 8000 Hz. Comma-decimals must degrade to Unknown, never half-parse; dot-thousands (`8.000` → reads as 8.0) is undetectable line-by-line and needs REW-dialect detection before Fletcher ever *interprets* such files. Losslessness (never rewriting foreign lines) is the standing protection. *(Partially addressed: parser degrades commas to Unknown; dialect detection open — Q-09)* **Update 2026-10-26:** APO itself turns every comma in a Filter line into a dot and reads an Fc like `8.000` as 8000 (rule in docs/research/apo-filter-semantics.md), so such lines ARE audible, and degrading them to Unknown hides audible filters from the curve. The REW importer applies APO's exact rule; the live-config parser still degrades them (open).
- **TB-19 · Incompatible fingerprints silently combined.** Libraries captured with different mic/rig types (in-ear mic vs. coupler, different smoothing, different calibration files) get bridged as if comparable. Interchange format must carry capture metadata — including which mic calibration was applied — and Fletcher must refuse or down-weight mismatched bridges. *(Open — Q-15)*
- **TB-20 · Measurement sweeps can hurt.** A sweep at full level into an IEM sitting in someone's ear is dangerous. Capture flows start quiet, ramp with confirmation, and never jump to full level without an explicit level-check step. Extends the prime directive. **Invariant since 2026-10-28 (ADR-0016): nothing Fletcher writes rises by more than 3 dB in one step** — `write_chain_safely` (the only writer of fletcher.txt) fades bigger rises in 1 dB steps, and typed increases over 3 dB ask first. Also covers what the review found: level matching off no longer lifts Flat to 0 dB; a positive trim can't outlive the outside Preamp line it offset; and exclusive-mode playback (Clip Studio, clip trials) now applies the Windows volume, trim and outside preamps it bypasses, instead of starting 10–20 dB above normal listening. *(Sweeps: open — Q-12. Control and playback jumps: addressed.)*
- **TB-21 · Loudness compensation with an invisible volume knob.** If the user rides an external amp's analog knob, the digital-volume anchor is silently wrong and the mode applies the wrong contour delta. Anchor invalidation must be detected where possible and the limitation stated plainly in the mode's UI. *(Open — Q-16)*
- **TB-25 · A preview that outlives its moment.** The inspector's "listen" writes fletcher.txt without moving the current node — if it survives past its context (pop-out closed mid-preview, a jump landing over it, app interruption), the user silently hears a chain that no UI claims is active. *(Addressed 2026-08-23: previews restore on panel unmount, on any real move — `applySnap` clears the restore point — and Rust emits a restore command when the pop-out window is destroyed. Launch-time `apply_side` also rewrites fletcher.txt deterministically.)*
- **TB-28 · Time-order error in paired comparisons.** In two-interval loudness judgments the second interval is systematically judged louder (or softer) by up to ~1 dB. Any paired protocol must randomize presentation order per trial (cancels it to first order) and should MEASURE it rather than assume it away. *(Addressed for the hearing profile 2026-08-23, ADR-0013: order randomized + order catches report it; correction deliberately not applied in v1.)*
- **TB-29 · A hardware knob turn mid-measurement is invisible.** The hearing profile (and any future capture) fixes its level in the digital domain; the hardware volume is undetectable (TB-21's physics). A knob change mid-session silently invalidates cross-band comparability. Mitigations: the session states the rule up front, interleaved scheduling spreads any drift across all bands, and between-staircase disagreement feeds the uncertainty as a max. *(Open by nature — unfixable without a mic.)*
- **TB-27 · The natural end of a track is a lifecycle, not a footnote.** Stop/replace paths raise the `stop` flag, but a track that simply RUNS OUT raises only `done` — every helper thread, waiter, or UI state keyed to `stop` alone leaks. Caught live 2026-08-23: the ~10 Hz pos emitter outlived its finished 30 s session forever, and the next session's clock flashed between two times. Any new session-scoped resource must exit on `stop OR done`, and short generated signals (which end naturally all the time) are the regression probe. *(Addressed 2026-08-23 for the pos emitter; audit any future session-scoped threads.)*
- **TB-30 · The wiring line vanishes underneath us.** An APO reinstall/reset (or another tool rewriting config.txt) drops `Include: fletcher.txt`. Every Fletcher write then lands in a file APO never reads: inaudible, and invisible too — the UI draws only what config.txt reaches, so imports show no curve and Add appears to do nothing. Caught live 2026-10-26 (config.txt back to APO's stock `Include: example.txt` + flat GraphicEQ). *(Addressed 2026-10-26: every fletcher.txt write goes through `write_fletcher_file`, which re-appends the one Include line if missing (ADR-0007, backup before first touch); launch-time `apply_side` makes it self-heal on startup. Other tools' lost lines, e.g. Peace's, are theirs to restore.)*
- **TB-26 · Outside writes during a blind session.** Any config write that isn't the session's own audition (a preview, an A/B flip, a preset switch) desynchronizes what's playing from what the trial believes is playing — the vote records against the wrong sound. *(Partially addressed 2026-08-23: `preview_chain` refuses while a session runs; `ab_flip` already cycles auditions instead of flipping. Still possible via preset switching or external tools mid-session — Q-05)*
- **TB-31 · Attenuation Fletcher may not edit, and no lever to answer it.** Level lives in two places Fletcher doesn't control: `Preamp:` lines in `config.txt` or another tool's file (ADR-0007 forbids editing them), and the derived `matched_preamp` (capped at 0 dB by `reference_db`, ADR-0003). Hit live 2026-08-29: a hand-added `Preamp: -10 dB` stacked with fletcher.txt's −10.9 for −20.9 dB, and the app could only go *quieter* — the readout showed the number while offering no way to change it. Addressed 2026-08-29 (ADR-0014): an output trim (−20…+12 dB) offsets it, and Settings names the foreign attenuation instead of leaving it unexplained. Standing rule: any level the UI *displays* must be one the user can either change or have explained.
- **TB-32 · APO installed, but not on this device.** APO is per-device. A Windows update or audio-driver reinstall can reset a device's effect slots and silently drop APO, while `HKLM\SOFTWARE\EqualizerAPO` still says "installed". When that happens everything looks fine (config.txt wired, fletcher.txt written, curve drawn) and nothing is audible. Hit live 2026-10-26: no active playback device had APO registered. The same happens if Windows' "Disable all enhancements" is on, or if the user switches to a device APO was never installed on. *(Addressed 2026-10-26: `apo::device_apo_status` reads the endpoint's FxProperties and Disable_SysFx; `eq_state` reports it for the default device and the EQ room shows a banner. The banner's button runs APO's own `DeviceSelector.exe` elevated and re-checks when it closes, and it offers any device that already has APO. The device menu tags devices without APO. Verified live with APO 1.4.2: the fix took effect immediately, no reboot. A device that gains APO during the run gets a "should be audible now, restart only if it isn't" note for older APO versions. Fletcher never writes FxProperties itself; that's APO's installer's job.)*
- **TB-33 · Update install mid-session.** Installing an update closes the app (the NSIS installer replaces and reopens it). Mid blind-trial or mid hearing-profile that silently throws the session away, and a playing track or calibration noise gets cut mid-buffer. *(Addressed 2026-10-26, ADR-0015: `update_install` refuses during a trial or profile session, checking both before AND after the download, since one may start while it runs; it stops cal noise and fades the track out, waiting for the device release, before handing over. At relaunch `apply_side` rewrites fletcher.txt deterministically, so a transient history preview cannot survive the restart.)*
- **TB-34 · Drawn ≠ played for shelves (and Q on LP/HP).** Fletcher writes `LS/HS … Q 0.707` and draws a center-frequency shelf, but APO reads an `LS`/`HS` line *with a Q* as a **corner**-frequency shelf and shifts it up (low) / down (high) by 10^(|gain|/80): ×1.19 at 6 dB, ×1.41 at 12 dB. So the curve, the matched preamp and every A/B level match involving an LS/HS filter describe a sound the user is not hearing. Related: `Biquad::rbj` forces Q = 1/√2 for LP/HP/LS/HS even when a different Q is written, which APO honours; and a foreign Q-less `NO` is drawn with Q 0.707 where APO uses 30. Found 2026-10-26 reading APO source (docs/research/apo-filter-semantics.md). *(Addressed 2026-10-26: `FilterSpec::biquad` now builds the filter APO plays, via `dsp::apo_resolve`. That covers the curve, matched preamp and A/B level matching, and also the in-app track engine, which had been PLAYING LS/HS at the drawn frequency in clip trials, so clip trials and system-wide A/B heard different filters. eq_state resolves unwritten Qs as APO does. From-live, AutoEQ and paste go through `own_filter`, so a bare foreign `LS`/`NO` keeps its sound when Fletcher writes it with a Q. Measured: a +6 dB LS was drawn up to 0.99 dB off. Tests: `dsp::tests::tb34_*`.)*
- **TB-35 · Two copies of Fletcher at once.** Nothing stopped a second launch (Start menu, autostart, clicking the shortcut while it sat in the tray), so copies piled up: four were found running at once on 2026-10-28. Each one writes fletcher.txt and registers Ctrl+Shift+A, so they overwrite each other's level/EQ and fight over the hotkey. *(Addressed 2026-10-28: `tauri-plugin-single-instance`, registered first; a second launch brings the existing window forward (`show_main_window`, shared with the tray) and exits. Verified live: second launch → still one process. Release and dev builds share the app identifier, so they also exclude each other.)*
- **TB-40 · The default device changes behind Fletcher's back.** Windows' sound settings, the taskbar speaker menu, another switcher or unplugging a DAC can all change the default playback device. Fletcher only re-read its state on config edits, so the device menu kept naming the old device (#8). A per-device preset (#7) has to follow every route too, not just Fletcher's own menu. *(Addressed 2026-10-29: `devices::watch_render_devices` registers an `IMMNotificationClient`; the backend reloads the UI on every default/state change and loads the new default device's preset, if it has one. The preset load goes through `preset_switch`, so it is refused mid-trial (TB-26) and fades any rise (TB-20); it is skipped during a hearing-profile session. A playing Clip Studio track reopens on the new device where it was (position, pause, loop, A/B side, level correction); a blind trial's stream is left to its own device recovery. Not yet handled: unplugging the device a track is playing on ends the stream before the switch arrives, so playback stops.)*
- **TB-41 · A global device hotkey steals a combination other apps use.** Ctrl+Shift+T (the cycle default) reopens the last closed tab in every browser, and a registered global hotkey takes it from them system-wide. Ctrl+Shift+digit is free in most apps but not all. *(Open: the user picked Ctrl+Shift 2026-10-29; device digits are opt-in per device; everything is remappable or can be switched off in Settings › Hotkeys.)*
- **TB-42 · A device claims an exclusive format it then refuses.** `IsFormatSupported` said yes and `Initialize` said no: 24-bit on a WH-1000XM6 on one PC (#9; every format there, so exclusive is impossible on it), and 24-bit on this PC's Realtek S/PDIF and NVIDIA HDMI outputs (16-bit opens). Fletcher committed to the first claimed format, so the test tone and Clip Studio's bypass failed with a raw `0x88890008`, and the shared fallback never fired. *(Addressed 2026-10-29: `playback::open_exclusive` walks every claimed format and only accepts one that initializes (default period, then aligned), never starting it, so `probe_rate` is still silent. None opens → `NoFormat` with a plain message: Clip Studio falls back to shared ("bypass unavailable"), clip trials and the hearing profile refuse as before. A device busy with another exclusive stream (Fletcher's own, mid-handoff) falls back to the claimed format, as before. Probe: `examples/excl_probe.rs`.)*
- **TB-43 · The A/B hotkey in hold mode meets a blind test or a lost release.** A trial starting while the key is held, or a release that never arrives (the key-up poll misses it), could leave the wrong side playing. *(Addressed 2026-10-30: during a trial the hotkey cycles the audition on each press as before and releases are ignored; outside one, press always goes to the held side and release to the resting side (absolute, not a toggle), so the next press and release put it right. Choosing a mode moves to its resting side.)*
- **TB-44 · A global hotkey stops responding after the app has run a long time; a restart fixes it.** Seen 2026-10-30, which hotkey not yet known; Ctrl+Shift+A has never done it, which points at the newer ones (Ctrl+Shift+O, Ctrl+Shift+T, device digits) that switch devices or show the popup on their own thread. Suspects, none reproduced: an action stuck mid-switch blocking later ones; hotkeys left unregistered by the remapping pause (`hotkeys_pause`) if the page reloads while a field is listening; work done inside the shortcut plugin's handler (main thread, under its lock), e.g. Ctrl+Shift+O focusing the window while a pop-out has focus. *(Open: next time, note which hotkey failed and whether Ctrl+Shift+A still worked.)*
- **TB-45 · A `Channel:` selection crosses an Include boundary.** APO does not document whether a selection made inside an included file survives it, or what a parent `Channel: L` before `Include: fletcher.txt` does to our lines (docs/research/apo-channel-selection.md). A split fletcher.txt left on `Channel: R` could put every later config.txt line on the right ear only. *(Addressed 2026-10-30 for our side: a split fletcher.txt opens AND ends on `Channel: all`. The opening one was found in review: a parent `Channel: L` before our Include would otherwise confine our preamp, and every fade step, to the left ear while the right ear's filters play unattenuated. An unsplit file writes no `Channel:` line, as before, and inherits a parent selection for preamp and filters alike. Readers start each file on both ears. Measured 2026-10-31: a `Channel: L` made inside an included file does not carry back to the parent (docs/research/apo-scope-and-loopback.md), so a selection never leaks out of fletcher.txt. Still open: whether a parent selection made before our Include applies inside it.)*
- **TB-46 · An imported source puts a Preamp on one ear only (a balance).** A preset has one preamp for both ears (ADR-0017), so `ConfigDoc::chains` drops it, and the copy loses that offset. The filters keep their ears. *(Open: carry it once balance exists; `eq_state` already sums it into that ear's curve.)*
- **TB-47 · An older caller edits a split preset as if it had one chain.** The current UI sends one list from `eq_state`'s filters (both ears' filters, mixed) without `right`; saving that would merge the ears for good. *(Addressed 2026-10-30: `set_fletcher_chain` refuses a split preset without `right`. Until the UI shows ears (Q-28), a split preset can't be edited, only joined with `chains_split`.)*
- **TB-48 · A split preset meets a UI path that still sends one chain.** Found in review 2026-10-30. The EQ page builds "the current chain" from `eq_state`'s filters, which holds both ears' filters mixed, without their ears.
