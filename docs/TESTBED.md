# Testbed

Every known edge case, captured the moment it's raised — before it's solved. Every design change gets checked against this list. Statuses: **Open**, **Addressed by <design/ADR>**.

**Prime directive:** Fletcher must never damage the user's existing audio setup. Failure modes may lose Fletcher's own state — never the user's config, and never their hearing (no surprise full-volume output).

---

- **TB-01 · APO absent.** Equalizer APO isn't installed, or is installed but not enabled for the selected device. Fletcher must detect both and guide, not silently no-op. *(Open)*
- **TB-02 · Peace owns the config.** User has an existing Peace (or hand-written) `config.txt`. Fletcher must not clobber it — coexist or migrate with explicit consent, and be cleanly uninstallable back to the prior state. *(Open — Q-03)*
- **TB-03 · Double processing in track mode.** Fletcher's own playback through the normal device path gets APO-processed on top of the in-app DSP. *(Open — Q-04)*
- **TB-04 · Exclusive-mode sources bypass APO.** ASIO / WASAPI-exclusive apps (audiophile players, some games) skip APO entirely; user concludes "EQ is broken." Detect/explain. *(Open)*
- **TB-05 · Device vanishes or renames.** USB DAC unplugged mid-session; Windows renames a device; config targets a device that no longer exists. *(Open)*
- **TB-06 · Clipping from positive gain.** Boost filters without preamp compensation clip digitally. Auto-preamp must account for filter *interaction* (summed response peak), not just the max single gain. *(Open)*
- **TB-07 · Sample-rate/format mismatch in track engine.** 44.1 kHz file, 48 kHz device; 24-bit; multichannel files. *(Open)*
- **TB-08 · Level matching hits the rails.** Matching a heavily-boosted config to bypass requires attenuation past comfortable listening, or gain past headroom. Define behavior + messaging. *(v1 fix decided 2026-08-23, scheduled with M3 of the Clip Studio plan: `matched_preamp` detects the clip-capped case — `to_reference > clip_safe` — and surfaces the shortfall instead of capping silently; the A/B bar and trial room then show "matched (short by X dB)" and session provenance records it. Context: `referenceDb` is a headroom budget — every chain must fit its peak-above-mean under 0 dBFS to reach the reference, which is why −8 is the default and 0 would break matching for any boosted chain. Full rails behavior still open — Q-06)*
- **TB-09 · External config edits while Fletcher runs.** Peace, a text editor, or another tool writes the config Fletcher is watching → reload loops or silent divergence from UI state. *(Open)*
- **TB-10 · Misleading small-N statistics.** 3/3 correct feels conclusive and isn't (p = 0.125). Stats display must not let users fool themselves — that's the whole point of the product. *(Open — Q-05)*
- **TB-11 · Crash during a bypass window.** If track mode temporarily blanks/modifies the device config (Q-04b) and Fletcher crashes, the user's EQ must come back on next boot/launch. Restore must be crash-proof (journaled/atomic). *(Open — Q-04)*
- **TB-12 · Blind test unblinds itself.** Any observable asymmetry between A and B — switch latency, crossfade audibility, UI tell, residual level difference — invalidates blinding. *(Partially addressed 2026-08-23, ADR-0012: clip trials run both chains in-engine through identical buffering with a 15 ms equal-power crossfade and gain-only trims — audit by ear on real material. System-material tests keep the config-swap path's inherent switch latency.)*
- **TB-13 · Clip battery picks bad clips.** Auto-extracted "bass-heavy" clip is actually a fade-out, cuts mid-phrase, or isn't representative — the whole systematic test inherits the error. Needs quality gates + manual override. *(Open — Q-11)*
- **TB-14 · Reinsertion variance in mic measurements.** Re-seating an in-ear mic or headphone shifts the measured response by several dB in the treble — easily larger than the differences being measured. Measurement mode must average multiple reseatings and report variance, or its "statistically identical" claim is false. *(Open — Q-12)*
- **TB-15 · Preference stats treated like discrimination stats.** A preference vote has no correct answer; reporting it with ABX-style "you scored 12/16" framing misleads. The two protocols need visibly different result presentations. *(Addressed 2026-08-23, ADR-0012: preference records carry `preferredA` + a two-sided p — never `correct`; verdicts read "preferred A — 12/16" / "no reliable preference"; the trial room presents unlabeled slots 1/2, reshuffled per trial; adaptive stopping is refused for preference because optional stopping inflates the apparent preference strength.)*
- **TB-16 · Inverse-filter blowup.** Deconvolution (HpTF matching, HRTF removal) naively inverts deep nulls into huge narrow boosts — audible ringing, clipping, possibly speaker/ear damage at high volume. Regularization and boost caps are mandatory. *(Open — Q-12, Q-13)*
- **TB-17 · The stock preset isn't neutral.** "Level-matched to everything" assumes the flat reference is actually bypass-equivalent (preamp 0, no filters). If the reference itself drifts (e.g. inherited preamp), every comparison is silently biased. *(Open — guarded by ADR-0003)*
- **TB-18 · Bridging overreach.** A bridged fingerprint (reviewer's library → user's ears via a shared headphone) is trustworthy mainly below ~5–6 kHz; presenting the full curve with uniform confidence invites false treble conclusions. Per-frequency confidence must be computed and *shown*. *(Open — Q-15)*
- **TB-24 · Peeking at interim results biases the test.** Watching live stats mid-session influences later answers (optional-stopping/expectation effects). Stats stay hidden by default during a session; revealing them shows a professional-toned caution and is recorded in the session's provenance so the result is honestly annotated. *(Open — Q-05)*
- **TB-23 · Hearing profile misread as an EQ target.** Equal-loudness across bands is natural hearing (ISO 226 contours), not a defect: naively EQ-ing the mic-free profile "flat" would sound wrong for everyone. The profile is meaningful only relative to population-average contours and only at its test loudness. Interpretation layer required before it ever drives a filter. *(Open — Q-19)*
- **TB-22 · Locale number formats in configs.** European REW exports (which APO reads, and users Include) write `Fc 50,0 Hz` and `Fc 8.000 Hz` meaning 8000 Hz. Comma-decimals must degrade to Unknown, never half-parse; dot-thousands (`8.000` → reads as 8.0) is undetectable line-by-line and needs REW-dialect detection before Fletcher ever *interprets* such files. Losslessness (never rewriting foreign lines) is the standing protection. *(Partially addressed: parser degrades commas to Unknown; dialect detection open — Q-09)* **Update 2026-10-26:** APO itself turns every comma in a Filter line into a dot and reads an Fc like `8.000` as 8000 (rule in docs/research/apo-filter-semantics.md), so such lines ARE audible, and degrading them to Unknown hides audible filters from the curve. The REW importer applies APO's exact rule; the live-config parser still degrades them (open).
- **TB-19 · Incompatible fingerprints silently combined.** Libraries captured with different mic/rig types (in-ear mic vs. coupler, different smoothing, different calibration files) get bridged as if comparable. Interchange format must carry capture metadata — including which mic calibration was applied — and Fletcher must refuse or down-weight mismatched bridges. *(Open — Q-15)*
- **TB-20 · Measurement sweeps can hurt.** A sweep at full level into an IEM sitting in someone's ear is dangerous. Capture flows start quiet, ramp with confirmation, and never jump to full level without an explicit level-check step. Extends the prime directive. *(Open — Q-12)*
- **TB-21 · Loudness compensation with an invisible volume knob.** If the user rides an external amp's analog knob, the digital-volume anchor is silently wrong and the mode applies the wrong contour delta. Anchor invalidation must be detected where possible and the limitation stated plainly in the mode's UI. *(Open — Q-16)*
- **TB-25 · A preview that outlives its moment.** The inspector's "listen" writes fletcher.txt without moving the current node — if it survives past its context (pop-out closed mid-preview, a jump landing over it, app interruption), the user silently hears a chain that no UI claims is active. *(Addressed 2026-08-23: previews restore on panel unmount, on any real move — `applySnap` clears the restore point — and Rust emits a restore command when the pop-out window is destroyed. Launch-time `apply_side` also rewrites fletcher.txt deterministically.)*
- **TB-28 · Time-order error in paired comparisons.** In two-interval loudness judgments the second interval is systematically judged louder (or softer) by up to ~1 dB. Any paired protocol must randomize presentation order per trial (cancels it to first order) and should MEASURE it rather than assume it away. *(Addressed for the hearing profile 2026-08-23, ADR-0013: order randomized + order catches report it; correction deliberately not applied in v1.)*
- **TB-29 · A hardware knob turn mid-measurement is invisible.** The hearing profile (and any future capture) fixes its level in the digital domain; the hardware volume is undetectable (TB-21's physics). A knob change mid-session silently invalidates cross-band comparability. Mitigations: the session states the rule up front, interleaved scheduling spreads any drift across all bands, and between-staircase disagreement feeds the uncertainty as a max. *(Open by nature — unfixable without a mic.)*
- **TB-27 · The natural end of a track is a lifecycle, not a footnote.** Stop/replace paths raise the `stop` flag, but a track that simply RUNS OUT raises only `done` — every helper thread, waiter, or UI state keyed to `stop` alone leaks. Caught live 2026-08-23: the ~10 Hz pos emitter outlived its finished 30 s session forever, and the next session's clock flashed between two times. Any new session-scoped resource must exit on `stop OR done`, and short generated signals (which end naturally all the time) are the regression probe. *(Addressed 2026-08-23 for the pos emitter; audit any future session-scoped threads.)*
- **TB-30 · The wiring line vanishes underneath us.** An APO reinstall/reset (or another tool rewriting config.txt) drops `Include: fletcher.txt`. Every Fletcher write then lands in a file APO never reads: inaudible, and invisible too — the UI draws only what config.txt reaches, so imports show no curve and Add appears to do nothing. Caught live 2026-10-26 (config.txt back to APO's stock `Include: example.txt` + flat GraphicEQ). *(Addressed 2026-10-26: every fletcher.txt write goes through `write_fletcher_file`, which re-appends the one Include line if missing (ADR-0007, backup before first touch); launch-time `apply_side` makes it self-heal on startup. Other tools' lost lines, e.g. Peace's, are theirs to restore.)*
- **TB-26 · Outside writes during a blind session.** Any config write that isn't the session's own audition (a preview, an A/B flip, a preset switch) desynchronizes what's playing from what the trial believes is playing — the vote records against the wrong sound. *(Partially addressed 2026-08-23: `preview_chain` refuses while a session runs; `ab_flip` already cycles auditions instead of flipping. Still possible via preset switching or external tools mid-session — Q-05)*
- **TB-31 · Attenuation Fletcher may not edit, and no lever to answer it.** Level lives in two places Fletcher doesn't control: `Preamp:` lines in `config.txt` or another tool's file (ADR-0007 forbids editing them), and the derived `matched_preamp` (capped at 0 dB by `reference_db`, ADR-0003). Hit live 2026-08-29: a hand-added `Preamp: -10 dB` stacked with fletcher.txt's −10.9 for −20.9 dB, and the app could only go *quieter* — the readout showed the number while offering no way to change it. Addressed 2026-08-29 (ADR-0014): an output trim (−20…+12 dB) offsets it, and Settings names the foreign attenuation instead of leaving it unexplained. Standing rule: any level the UI *displays* must be one the user can either change or have explained.
- **TB-32 · APO installed, but not on this device.** APO is per-device. A Windows update or audio-driver reinstall can reset a device's effect slots and silently drop APO, while `HKLM\SOFTWARE\EqualizerAPO` still says "installed". When that happens everything looks fine (config.txt wired, fletcher.txt written, curve drawn) and nothing is audible. Hit live 2026-10-26: no active playback device had APO registered. The same happens if Windows' "Disable all enhancements" is on, or if the user switches to a device APO was never installed on. *(Addressed 2026-10-26: `apo::device_apo_status` reads the endpoint's FxProperties and Disable_SysFx; `eq_state` reports it for the default device and the EQ room shows a banner. The banner's button runs APO's own `DeviceSelector.exe` elevated and re-checks when it closes, and it offers any device that already has APO. The device menu tags devices without APO. Verified live with APO 1.4.2: the fix took effect immediately, no reboot. A device that gains APO during the run gets a "should be audible now, restart only if it isn't" note for older APO versions. Fletcher never writes FxProperties itself; that's APO's installer's job.)*
- **TB-33 · Update install mid-session.** Installing an update closes the app (the NSIS installer replaces and reopens it). Mid blind-trial or mid hearing-profile that silently throws the session away, and a playing track or calibration noise gets cut mid-buffer. *(Addressed 2026-10-26, ADR-0015: `update_install` refuses during a trial or profile session, checking both before AND after the download, since one may start while it runs; it stops cal noise and fades the track out, waiting for the device release, before handing over. At relaunch `apply_side` rewrites fletcher.txt deterministically, so a transient history preview cannot survive the restart.)*
- **TB-34 · Drawn ≠ played for shelves (and Q on LP/HP).** Fletcher writes `LS/HS … Q 0.707` and draws a center-frequency shelf, but APO reads an `LS`/`HS` line *with a Q* as a **corner**-frequency shelf and shifts it up (low) / down (high) by 10^(|gain|/80): ×1.19 at 6 dB, ×1.41 at 12 dB. So the curve, the matched preamp and every A/B level match involving an LS/HS filter describe a sound the user is not hearing. Related: `Biquad::rbj` forces Q = 1/√2 for LP/HP/LS/HS even when a different Q is written, which APO honours; and a foreign Q-less `NO` is drawn with Q 0.707 where APO uses 30. Found 2026-10-26 reading APO source (docs/research/apo-filter-semantics.md). *(Addressed 2026-10-26: `FilterSpec::biquad` now builds the filter APO plays, via `dsp::apo_resolve`. That covers the curve, matched preamp and A/B level matching, and also the in-app track engine, which had been PLAYING LS/HS at the drawn frequency in clip trials, so clip trials and system-wide A/B heard different filters. eq_state resolves unwritten Qs as APO does. From-live, AutoEQ and paste go through `own_filter`, so a bare foreign `LS`/`NO` keeps its sound when Fletcher writes it with a Q. Measured: a +6 dB LS was drawn up to 0.99 dB off. Tests: `dsp::tests::tb34_*`.)*
