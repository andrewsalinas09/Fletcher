## 2026-10-26 (night) — v0.2.0 shipped; REW import (issue #1), and APO's real filter semantics

- **Did:** Cut **v0.2.0**, the first release with the updater: bump script, CHANGELOG notes, tag, CI build, draft, then the user pressed Publish. The pipeline worked end to end. v0.1.0 had 27 downloads and no updater, so those users can only be reached where the link was shared. Then GitHub issue #1, REW filter import. A probe showed today's parser read REW's PK/LP/HP/LPQ/HPQ/LS/HS/NO/AP but **silently dropped** `Modal` and the `LS/HS 6dB/12dB` shelves, and dropped *everything* in European-locale exports. Read APO's own source (BiQuadFilterFactory/BiQuadFilter/BiQuad.cpp, GitHub mirror) for the exact rules and recorded them in `docs/research/apo-filter-semantics.md`. Built `fletcher_core::rew`: header detection, APO's exact number rules (comma → dot, `8.000` Fc → 8000), and every Generic type mapped onto an *identical* biquad in Fletcher's exact-drawing kinds (PK/LPQ/HPQ/BP/NO/AP/LSC/HSC with explicit Q; shelves go corner→center and S→Q). Unplayable lines are returned with reasons, never dropped. A test ports APO's shelf code line for line and asserts every spelling matches to 1e-9 dB over 200 frequencies. `rew_import` turns a file into a new preset (shared `import_as_preset` with AutoEQ) and recognises REW's binary `.req` save with a helpful message. Ctrl+V of a REW export uses the same reader. UI: "From REW file…" in the preset menu.
- **Learned:** APO's `LS 6dB` isn't first-order; it's the same biquad with S = 0.5. A Q-less `NO` is Q 30. And the big one: **an `LS`/`HS` line with a Q is a corner-frequency shelf in APO**, while Fletcher writes `LS … Q 0.707` and draws it as center-frequency. So every LS/HS Fletcher has drawn is ~0.25 oct off from what plays at ±6 dB (**TB-34**). TB-22 updated: comma lines are audible in APO, so degrading them to Unknown hides real filters.
- **Did (cont.):** The user's first export was a `.req`, REW's Java-serialized save file, with all 28 slots `NONE`. The second, a real REW 5.31.3 text export of every Generic type, became a fixture and exposed newer names. Two-word `LP Q`/`LS Q` were being dropped, because a bare `Q` was read as the parameter; fixed. `Notch`/`All pass` are silent in APO and now import as NO/AP. `LP1`/`HP1` (first-order; APO misplays them as second-order) and `L-T` are skipped with reasons. Result: 17 imported, 3 skipped, each named. The live test showed two UI bugs, both fixed. Unrounded Q in the strip (now `fmtQ`, 3 places; the clipboard keeps full precision). A chain below the scale painted over the axis labels: a clip path stopped that but left fragments, so curves now ride the plot edge (`yOfPinned`) and stay one continuous line. Then **fixed TB-34** at the root: `FilterSpec::biquad` goes through `dsp::apo_resolve` (APO's rules: Q honoured on LP/HP, LS/HS-with-Q is a corner shelf, bare NO is Q 30, bare shelf is S 0.9, Q-less PK plays nothing). `shelf_center_q` moved into `dsp`, shared with `rew`. `eq_state` keeps q as an Option. From-live, AutoEQ and paste adopt foreign lines through `own_filter`, which preserves their sound when Fletcher writes them with a Q.
- **Learned (cont.):** TB-34 wasn't only cosmetic. The in-app **track engine** uses `FilterSpec::biquad`, so clip trials had been *playing* LS/HS at the drawn frequency while system-wide A/B played APO's. The two paths heard different filters. Measured: a +6 dB LS was drawn up to 0.99 dB off. A REW fixture from the user's own install beat the 2013 sample. Real exports have drifted from what APO was built against.
